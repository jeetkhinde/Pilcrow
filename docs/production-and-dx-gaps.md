# Pilcrow: Production-Grade & Agent-First DX Gap Analysis

> As of 2026-04-24. ISR, SSG, named actions, param matchers, fragment directories, and
> streaming all shipped. This document covers what remains.

**Key finding:** Several "missing" features are already implemented but invisible to agents.
`routes::products_id("42")` is generated by `routes_codegen.rs` right now. `env::Private::load()`
is generated by `env_codegen.rs`. CSRF exists in `runtime/src/csrf.rs`. The discoverability gap
— not in registry, not surfaced by MCP, no canonical usage — means agents write string-literal
URLs and manual `std::env::var` calls instead. Fixing the knowledge surface is as important as
shipping new features.

---

## Part 1 — Production-Grade Gaps

| # | Gap | What exists today | Root cause | Severity |
|---|---|---|---|---|
| 1 | **No graceful shutdown** | `axum::serve(listener, app).await.expect("serve")` — no signal handler | `start.rs:48` has no `with_graceful_shutdown()` | **Critical** — in-flight requests killed on SIGTERM/pod restart |
| 2 | **CACHE_VARY not applied to cache key** | Constant is parsed and stripped; noted as "v2" in ISR memory | `IsrCache` key is `req.path` only — user/session header variants return same cached HTML | **Critical** — silent data leak if ISR page reads `Locals<User>` |
| 3 | **ISR cache is in-memory only** | `IsrCache(Arc<Mutex<HashMap<...>>>)` — lost on restart | Redis/SQLite backends deferred; no file-system fallback | **Critical** for multi-instance and rolling deploys |
| 4 | **ISR background revalidation errors silently swallowed** | `tokio::spawn(async { revalidate... })` — no error surface | Background task panic drops silently; stale entry stays stale forever | **High** — invisible production failures |
| 5 | **No request-level observability spans** | `tracing::warn!`/`tracing::error!` used in library code | No `tracing::Span` per request — no method, path, status, duration, trace-id | **High** — production debugging is terminal-grep-only |
| 6 | **No request timeout** | `axum::serve()` with no timeout layer | Long-running `load()` or action fns hold executor threads indefinitely | **High** |
| 7 | **PRERENDER + REVALIDATE mutually exclusive** | Build panic if both declared — by design | Startup-prerender model deferred this combination | **High** — the natural SSG lifecycle is prerender-then-revalidate |
| 8 | **No persistent ISR cache across restarts** | In-memory only — all prerendered pages cold on restart | `pilcrow export` CLI not started | **High** — SSG pages re-render on every deploy |
| 9 | **No adapter system** | `TcpListener::bind(addr)` baked into `start.rs` | Architecture assumes tokio standalone | **High** — blocks Lambda, Cloudflare Workers, Vercel |
| 10 | **No TLS / HTTPS support** | Bare TCP; no rustls/tower-tls | Out of scope, but no documented reverse-proxy integration | **Medium** |
| 11 | **No rate limiting** | tower-governor works but zero integration | Not wired as middleware layer in `start.rs` | **Medium** |
| 12 | **`pilcrow export` CLI missing** | `pilcrow_start` prerendering runs at boot; no `dist/` output | CLI doesn't have `export` command | **Medium** — blocks pure CDN/static deployment |

### Quickest wins for production

**Graceful shutdown** — 5 lines in `start.rs` (`runtime/src/start.rs:48`):

```rust
axum::serve(listener, app)
    .with_graceful_shutdown(async {
        tokio::signal::ctrl_c().await.ok();
    })
    .await
    .expect("serve");
```

**Request tracing** — add `tower_http::trace::TraceLayer` to `start.rs`. One layer, zero app
code changes, gives every request a span with method/path/status/latency.

**CACHE_VARY** — the `IsrCacheState` lookup in codegen already receives `req`; it needs to hash
the specified header/cookie values alongside `req.path` when building the cache key.

## Part 2 — Agent-First DX Gaps (Token & Line Reduction)

### 2a — Already Implemented, Invisible to Agents

These exist in the codebase right now. Agents write verbose workarounds because the MCP does not
surface them.

| Gap | What exists | What agents write instead | Fix |
|---|---|---|---|
| **Type-safe route helpers** | `routes_codegen.rs` generates `pub mod routes { pub fn products_id(id: &str) -> String }` — included via `generated_typed_routes.rs` in `pilcrow_app!()` | `redirect("/products/42")` string literals — dead links undetected until runtime | Register `typed-routes` in `registry.toml`, add `canonical_usage`, add validation rule suggesting `routes::` over string literals |
| **Typed env vars** | `env_codegen.rs` generates `env::Private::load()?` and `env::Public::load()?`; registered as `env-config` stable | `std::env::var("DATABASE_URL").unwrap_or_default()` — untyped, panics on missing vars | Add `canonical_usage` showing `env::Private::load()?` in middleware; add guidance on caching the result in `Locals` |
| **CSRF middleware** | `runtime/src/csrf.rs` exists, re-exported as `pilcrow_web::__csrf_middleware` | Agents skip CSRF or implement their own token check | Register as a feature with canonical setup example |

These three require **zero new code** — only `registry.toml` + `docs.rs` additions.

### 2b — Missing: High-Impact Code Reductions

| # | Missing | Current agent pattern | Proposed pattern | Lines saved |
|---|---|---|---|---|
| 1 | **`req.form.parse::<T>()`** — serde Deserialize for form bodies | `let name = req.form.get("name").unwrap_or(""); let price = req.form.get("price").unwrap_or("0").parse::<f64>().unwrap_or(0.0);` — 1 line per field | `#[derive(Deserialize)] struct Input { name: String, price: f64 }` + `let input: Input = req.form.parse()?;` | **4–10 lines per action fn** |
| 2 | **`Req::for_test()`** — public test constructor | No unit tests for `load()` — agents write integration tests or skip tests entirely | `let req = Req::for_test().param("id","42").query("page","1").build();` then `load(req).await` | Enables `load()` unit testing at all |
| 3 | **Form validation macro** | `if field.is_empty() { errs = errs.error("field","required").value("field", field); }` — 1 block per field | `let input = validate!(req.form { name: required, email: required \| valid_email })?;` | **3–4 lines per validated field** |
| 4 | **`DeferredHtml` slot name inference** | `DeferredHtml::spawn("product_list", loading_html, async { ... })` — slot name repeated, misspelling is silent bug | Slot name inferred from struct field name by the macro | **Eliminates silent misspelling bug** |
| 5 | **`env::Env` startup singleton** | `let env = env::Private::load()?;` written in every `load()` that needs it — loaded repeatedly | `Env::private()` returns an `Arc`-cached singleton populated at startup | **2 lines per load() using env vars** |

#### `req.form.parse::<T>()` — why this is the top priority

Every form handler in every Pilcrow app currently contains a block like:

```rust
// current — agents write this for every form field
let name = req.form.get("name").unwrap_or("");
let email = req.form.get("email").unwrap_or("");
let price = req.form.get("price").unwrap_or("0").parse::<f64>().unwrap_or(0.0);
let active = req.form.contains("active");
```

With `FormMap::parse::<T>()`:

```rust
// proposed — full struct deserialization, Rust type safety, ? propagates errors
#[derive(serde::Deserialize)]
struct CreateInput {
    name: String,
    email: String,
    price: f64,
    #[serde(default)]
    active: bool,
}

let input: CreateInput = req.form.parse()?;
```

This eliminates the single largest category of agent-generated boilerplate in the codebase.
Implementation: `FormMap` collects values into a `serde_urlencoded`-compatible map and calls
`serde_urlencoded::from_str` or equivalent — the `serde` dep is already in the tree via
`serde_json`.

### 2c — Agent Infrastructure (MCP + Tooling)

| # | Gap | Impact on token consumption | Fix |
|---|---|---|---|
| 1 | **`silcrow-mcp` search returns 0 for natural queries** | Agents asking about "SSE", "WebSocket", "reactive bindings" get no results — hallucinate silcrow APIs | Add natural-language aliases in tag index (`sse → s-sse → server-sent-events`); fix search scoring to weight tag matches |
| 2 | **`suggest_pattern` MCP tool absent** | Agent must know feature IDs, call `get_feature_spec`, interpret `canonical_usage` — 2–3 tool round trips minimum | One tool: input `"page with 60s cache and real-time counter"` → outputs exact code skeleton. Eliminates hallucinated patterns. |
| 3 | **No `inspect_isr_cache` dev endpoint** | Agents debugging ISR/SSG issues must add print statements or tail logs | `GET /__pilcrow_dev/isr` in dev mode returns JSON cache state per key (age, TTL, tags, `is_revalidating`) |
| 4 | **`scan_project_context` always full** | Every agent session re-scans the entire route tree even if unchanged | A `project_fingerprint` tool (hash of discovered routes + page options) — skip full scan if unchanged. Saves 2–4 tool calls per session on stable projects. |
| 5 | **`validate_implementation` gaps for new features** | ISR (`REVALIDATE`, `MAX_STALE`, `CACHE_TAGS`) and SSG (`PRERENDER`, `entries()`) constants not covered | Add validation rules for ISR/SSG constants to `validation.rs` so agents catch errors before `cargo build` |
| 6 | **Ghost `s-panel` tag in silcrow-mcp** | Agents get a tag hit, try to use `s-panel`, fail at runtime — it doesn't exist in `silcrow.js` | Remove from the silcrow-mcp tag index, or document it if it is planned |
| 7 | **`pilcrow new` lacks composition flags** | Agents bootstrapping auth+DB apps write middleware, env setup, and DB init from scratch every time | `pilcrow new --with-auth --with-postgres` generates `src/middleware.rs` with session auth stub, `Pilcrow.toml [env]` with `DATABASE_URL`, and a working DB `Locals` pattern |

## Part 3 — Prioritized Roadmap

Ranked by: *does this block a real agent-built app from shipping?*

```
Tier 0 — Zero-code fixes (MCP/registry only)
  1. Register `typed-routes` in registry.toml + canonical_usage
  2. Add canonical_usage for env-config showing middleware singleton pattern
  3. Register CSRF feature with setup example
  4. Fix silcrow-mcp search (natural-language aliases for SSE/WS/bindings)
  5. Remove ghost s-panel tag from silcrow-mcp
  6. Add validate_implementation coverage for ISR/SSG constants

Tier 1 — Production blockers (< 50 lines of Rust each)
  7.  Graceful shutdown in start.rs (axum API, ~5 lines)
  8.  TraceLayer in start.rs (tower_http, ~2 lines + Cargo.toml dep)
  9.  Request timeout layer (tower, ~3 lines)
  10. CACHE_VARY applied to ISR cache key
  11. Background revalidation error logging (log panic, mark entry for retry)

Tier 2 — DX multipliers (medium effort, highest agent token reduction)
  12. req.form.parse::<T>() — serde Deserialize for FormMap (biggest single token saver)
  13. Public Req::for_test() constructor (unlocks load() and action unit tests)
  14. PRERENDER + REVALIDATE combined (prerender at startup, then TTL revalidation)
  15. suggest_pattern MCP tool

Tier 3 — Production completeness
  16. File-based ISR cache backend (survives restarts; no external dependency)
  17. pilcrow export CLI (PRERENDER pages → dist/ for CDN)
  18. Adapter trait (TcpListener as default; Lambda handler as alternate)
  19. inspect_isr_cache dev endpoint
  20. pilcrow new --with-auth --with-postgres scaffold flags
  21. Form validation macro
  22. env::Env startup singleton
```

The leverage ratio for **Tier 0 + Tier 1** is enormous: roughly a day of work closes the most
visible production gap (graceful shutdown, tracing) and makes the features that already exist
discoverable to agents.

**Tier 2 item 12** (`req.form.parse::<T>()`) alone would cut 30–40% of token output in any
agent session writing form-heavy pages, because it eliminates the most common boilerplate
pattern in Pilcrow app code.
